# Security policy

## Supported version

The protected `main` branch is the only supported version. Reports should identify the exact affected
commit.

## Reporting a vulnerability

If GitHub's **Report a vulnerability** flow is available in this repository's Security tab, use it.
Otherwise, open a public issue containing no vulnerability details and ask @NWarila to establish a
private reporting channel. Do not put vulnerability details or secrets in a public issue.

Include the affected commit; the relevant checker, `Containerfile`, or workflow path; reproduction
steps; and potential impact. Maintainers aim to acknowledge a report within three business days and
provide an initial assessment within seven business days.

Never include credentials, tokens, private keys, private repository contents, or other sensitive
material in a public report.
